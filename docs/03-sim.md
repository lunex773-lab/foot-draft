# 試合シミュレーション（暫定）

実装：`packages/shared/src/sim/engine.ts`　バージョン：`SIM_VERSION = 0.2.0`

| バージョン | 内容 |
| --- | --- |
| 0.1.0 | 初版（自動生成の240人で調整） |
| 0.2.0 | 選手データベース v1（300人）に対応。特殊能力を12種類に入れ替え、能力の水準をカードのOVRに合わせる補正を追加、カウンターと決定機の確率を再調整 |
バランス検証：`npm run sim:balance -- 150`（`packages/shared/scripts/balance.ts`）

## 1. 全体の流れ

- 90分を15分ずつ6区間に分けて進める（設計書 6-1）。
- 1試合は「ポゼッション（攻撃の1回）」の連続。1回のポゼッションは次の局面を通る。

```
ビルドアップ(自陣) ─成功→ 中盤 ─成功→ アタッキングサード ─成功→ シュート
   │失敗               │失敗              │失敗
   ├ 相手のプレス奪取    ├ 相手のカウンター   ├ CK / FK / PK / ミドルシュート
   └ ボール保持を続ける   └ ボールを下げる     └ 相手ボール（カウンターの可能性）
ロングボール：中盤を飛ばして前線へ（空中戦・スピード勝負）
```

- 各局面は「攻撃側の部隊の能力」と「守備側の部隊の能力」の勝負で、成功確率は
  `logistic((攻撃側 − 守備側) / 8 + 局面ごとの補正)`。
- 部隊の能力は、ピッチ上の選手の内部能力（設計書 4-2）を役割ごとに重み付けして平均したもの。
  チーム総合値だけで勝敗を決めない（設計書 6-3）。
- 経過時間はポゼッションごとに進み、ボールを持っていた時間の割合が支配率になる。
- 乱数は試合ごとのシードから作るので、同じ入力・同じシードなら同じ試合になる（設計書 6-4）。

## 2. 考慮している要素（設計書 6-3）

| 要素 | 反映のしかた |
| --- | --- |
| 選手能力 | 局面ごとに使う内部能力が違う（例：ビルドアップ＝ショートパス・ボールコントロール・視野・ロングパス）。内部能力の比率はデータベースの値、全体の水準はカードのOVRに合わせる（係数＝OVR ÷ 主ポジションでの内部能力評価） |
| ポジション | 適性外では能力 ×0.80〜0.93（GKは別扱い）。CFはST枠、LWB/RWBはLB/RB枠で減点なし。フォーメーションの枠ごとに部隊を決める |
| 役割（プレースタイル） | ケミストリーと、シュート・アシストを担う選手の選び方に反映 |
| 特殊能力 | データベースの12種類。すべて条件付きで発動（`data/traits.ts` に発動条件を明記、下表）。条件に合わない選手（例：GK以外のSweeper Keeper）では発動しない |
| フォーメーション | 枠の位置で、どのサイドに誰がいるかが決まる（攻撃方向・相手の弱いサイドとの関係） |
| 攻撃戦術 | ポゼッション：保持・前進に＋、失敗してもボールを下げてやり直す。カウンター：奪った後に速攻。ロングボール：中盤を飛ばす |
| 守備戦術 | ハイプレス：相手のビルドアップを奪いやすいが、スタミナ消費が増え、ロングボールと背後を突かれやすい。ローブロック：ゴール前は堅いが押し込まれ、CK・ミドルシュートが増える |
| その他設定 | 攻撃方向・守備ライン・テンポ・パス傾向・プレス強度（それぞれ小さな補正） |
| ケミストリー | 0〜100点 → 能力 ×0.94〜1.06 |
| スタミナ・疲労 | 区間ごとに減る（ポジション・戦術・特性で量が変わる）。能力は最大約 −22% |
| 試合状況 | 60分・75分の時点で、負けていれば攻撃的に、勝っていれば守備的に切り替える（編成画面の設定） |
| 控え選手 | 60分・75分の時点で疲れた選手を交代（最大3人）。負けて攻撃的に切り替えた時はFWを優先して入れる |
| 乱数 | 試合ごとのシード |

### 特殊能力の効果

| 特殊能力 | 発動条件と効果 |
| --- | --- |
| Engine | 全ポジション：スタミナ消費 −25% |
| Counter Runner | FW・MF枠：カウンター発生率 +8%/人（2人まで）、カウンター局面のスピード +5/人 |
| Sweeper Keeper | GK枠のみ：相手のカウンター・裏抜けの守備 +4（守備ラインが高い時 +6） |
| Cross Specialist | サイド枠のみ：そのサイドの攻撃でクロスを選ぶ率 +10%/人、本人のクロスからの xG ×1.2。出場中はCK・FKの質 +3 |
| Press Resistant | DF・MF枠：ビルドアップ +2/人（最大+4）、中盤の前進 +1/人（最大+2） |
| Clinical Finisher | 本人のシュート（ミドル・ヘディング以外）：xG ×1.15。GKは打たないため発動しない |
| Leader | 出場中：ケミストリー +3（2人まで）、負けている終盤の能力低下を緩和 |
| Long Shot | 本人のミドルシュート・直接FK：xG ×1.5、キッカー・ミドルを任されやすい |
| Aerial Threat | 空中戦 +8（攻守）、本人のヘディング xG ×1.4 |
| Ball Winner | DF・MF枠：中盤の守備 +2/人（最大+4）、プレス +1/人（最大+3） |
| Speedster | カウンター・裏抜けの局面のみ：スピード +8（2人まで） |
| Playmaker | MF・FW枠：中盤の前進 +2/人（2人まで）、本人のパスからの決定機 xG ×1.15 |

## 3. 決定機とゴール

- 決定機の種類ごとに基本のゴール期待値（xG）を持つ（例：スルーパス 0.135、クロスからのヘディング 0.056、カウンター 0.16、PK 0.76）。
- xG ＝ 基本値 ×（シュートを打つ選手の決定力）×（相手の守備の圧力）× 特性補正。
- ゴール確率 ＝ xG ×（相手GKの能力による補正）。それ以外はセーブ・ブロック・枠外。

## 4. 選手評価・MVP

6.0 から出来事ごとに加点・減点（ゴール +1.0〜1.2、アシスト +0.5、決定機を作る +0.12、セーブ +0.22〜0.45、失点 GK −0.3・DF −0.12、警告 −0.3、退場 −1.5、勝利 +0.3、無失点 +0.4）。3.0〜10.0 に収め、最高評価をMVPにする。

## 6. 既知の課題（ベータテストで調整）

- データベースの攻撃陣は守備陣よりスピードが高く、カウンターがシュートの約35%を占める（実際より多い）。
- 「ポゼッション＋ローブロック」がやや強い（1.53）。
- スネークドラフトでは4チームの戦力差が小さくなりやすく、戦術と相性の比重が大きい（ドラフトの公平性としては良い面もある）。
- 退場は1試合0.15件で、実際より少し多い。
- 処理時間は1試合約2〜4ms（Node.js）。Workers の CPU 時間制限を考えると、本番は有料プランを前提にする。
