# 開発計画：Phase 7（ベータテスト）

設計書 22「Phase 7：友人テスト・10〜30人程度から開始・テスト用GEMS・継続率測定・フィードバック収集・SIMバランス調整・UI改善」と、設計書 12-2（Matches・Draft Analytics・Beta Testing）・15（ベータテスト管理）・23-5。
ユーザーに確認して決めた内容は `docs/02-decisions.md` の 60〜67。

## 1. 現状

| 項目 | 状態 |
| --- | --- |
| ユーザーのタグ | Founder・Beta Tester・Friend Tester・Developer・Normal（Phase 5）。登録時は Normal。管理サイトの Users で変更できる |
| テスト用の付与 | 管理サイトの Economy から1人ずつ（staging・ローカルのみ） |
| GEMS 配布 | 無償GEMS をタグ・指定ユーザーなどへ（Phase 5） |
| 継続率・分析 | Analytics・Retention でタグごとに比較できる（Phase 5） |
| フィードバック | 送信・返信・状態管理（Phase 5） |
| 模擬ストア | staging・ローカルで購入を試せる（Phase 6） |

| ドラフトの制限時間 | 8秒（プライベートルームはホストが 5・8・10・15 秒から選ぶ） |

## 2. 設計

| 項目 | 設計 |
| --- | --- |
| ベータの環境（決定 60） | staging。開発中の変更は今までどおり自動で公開される。公開の瞬間に通信が切れても再接続で続きから遊べる（ルームの状態は保存済み）。ゲームが古い版のまま開かれている時は「新しい版があります（再読み込み）」を表示 |
| テスト用アカウントの除外 | 本番以外で `check_` で始まるユーザー名の登録は Developer タグにする（Staging check 用）。既存の `check_…` もマイグレーションで Developer に変更。Overview・Analytics・Retention・ベータレポートは「Developer を除く」を初期値にする（切り替え可） |
| 参加（決定 61） | 誰でも登録できる。管理サイトの Beta Testing でユーザー名をまとめて入力してタグ（Friend Tester など）を付ける |
| テスト用通貨（決定 62） | 自動配布なし。必要な時は、無償GEMS は GEMS 配布、COINS・有償GEMS はテスト付与（タグ単位で一括も可能に。staging・ローカルのみ） |
| レポート（決定 63） | 期間を決めず、管理サイトの Beta Testing でいつでもその時点のレポートを表示・Markdown で保存。設計書 15-3 の指標（D1・D7・D30、平均プレイ時間、平均対戦回数、ドラフト完了率、試合完了率、途中退出率、フィードバック件数、再訪率、機能別利用率）＋リーグ後の評価＋制限時間の比較 |
| ホーム画面に追加（決定 64） | Web アプリのマニフェストとアイコン、iOS 用の設定。追加するとアドレスバーなしの全画面で開く |
| リーグ後の評価（決定 65） | リーグの結果画面で「ドラフトは楽しかった？」「試合結果は納得できた？」を5段階（任意・飛ばせる）。1日（日本時間）1回まで。モード・制限時間・フォーメーション・順位と一緒に保存し、管理サイトで集計 |
| 制限時間の比較（決定 66） | クイックドラフト・ランク戦・Collection Draft のルームを 8秒と12秒に半分ずつ割り当てる（ルームの ID から決めるので同じルームの全員が同じ秒数）。設定は管理サイトで「比較する／○秒に固定」を切り替え。時間切れ率・自動指名率・ドラフト完了率・途中退出率・評価を秒数ごとに比較。プライベートルームの選択肢に 12秒を追加 |
| テストデータのリセット（決定 67） | ユーザー単位・タグ単位。通貨（台帳に「テストのリセット」として記録して0に）・交換ポイント・コレクション・Collection Draft の登録・ガシャの天井・ミッションの進みと受け取り・Season Pass を初期状態に。アカウント・タグ・対戦記録・レーティング・各種履歴・フィードバック・分析データ・購入記録・会員は残す。staging・ローカルのみ、admin 以上、操作ログに記録 |
| Matches（試合統計） | 期間・モードで絞り込み。試合数・1試合の平均得点・引き分け率・点差の分布・シュート・xG・支配率、フォーメーション別・攻撃戦術別・守備戦術別の勝率と得失点、ケミストリーと勝率、総合力の低いチームが勝った割合 |
| Draft Analytics（ドラフト統計） | 指名順ごとの平均 OVR、よく早く指名される選手、ポジション別の指名の早さ、レアリティ別、自動指名率・時間切れ率（秒数ごと）、ドラフト完了率 |
| フィードバックと利用履歴（設計書 23-5） | フィードバックの詳細に、送った人の最近の利用（セッション・対戦数・最後に遊んだモード）とユーザー詳細へのリンク |
| BETA 表示 | ゲームのヘッダーに BETA、初回だけベータの説明（感想の送り方）を表示 |

## 3. データ（マイグレーション 0008）

- `app_settings`（設定：ドラフトの制限時間の比較）
- `league_ratings`（リーグ後の評価。ユーザー×日で一意、ユーザー×ルームでも一意）
- `test_resets`（リセットの記録：誰が・誰を・いつ・何を戻したか）
- 既存の `check_…` ユーザーのタグを Developer に

## 4. 実装順序

1. api：マイグレーション 0008、テスト用アカウントの扱い、制限時間の割り当て、評価、リセット、タグの一括設定、タグ単位のテスト付与、Matches・Draft Analytics・ベータレポートの API（結合テスト）
2. web：評価、BETA 表示と説明、新しい版の通知、ホーム画面に追加、プライベートルームの 12秒
3. admin：Beta Testing（テスター・リセット・付与・レポート・制限時間の設定）、Matches、Draft Analytics、フィルターの「Developer を除く」、フィードバックの利用履歴
4. UI の見直し（スマートフォン幅を中心に主要画面）
5. ブラウザでの確認、staging への公開と確認、ベータの案内（`docs/11-beta-guide.md`）、ドキュメント、コミット

## 5. この Phase で行わないこと

- 実際の友人テストの実施とベータテストレポートの作成：あなたが友人を招待して遊んでもらった後、管理サイトのレポートと実際のデータをもとに作る（データがないうちに結果を書かない：設計書 0-4）
- SIM の数値の調整：ベータのデータ（Matches・Draft Analytics・評価）を見てから行う
- iOS・Android アプリ（Phase 8 の前に作る：決定 64）
- 管理サイトの Exchange（交換所管理）・Missions（ミッション管理）ページ
