# 開発計画：Phase 6（課金・運営）

設計書 22「Phase 6：Apple・Google 購入検証・Season Pass・Premium Membership・商品管理・売上分析・シーズン報酬・管理画面のガシャ管理」と、設計書 11・12-8・20-3。
ユーザーに確認して決めた内容は `docs/02-decisions.md` の 52〜58。

## 1. 現状

| 項目 | 状態 |
| --- | --- |
| クライアント | Web 版のみ（React）。iOS・Android アプリはまだない → Apple・Google の購入は実際には行えない（決定 52） |
| 有償GEMS | 残高は購入分・配布分に分けて保持済み（Phase 4）。購入による付与の経路はない |
| シーズン報酬 | 実装済み（Phase 4：ランク戦の最終順位で無償GEMS） |
| ガシャ | 2つ（Standard・Premium シリーズ1）をマイグレーションで作成。管理サイトからの作成・編集はない |

## 2. 設計レビュー

| 確認項目 | 設計 |
| --- | --- |
| 購入の流れ | ①ゲームが購入を開始（サーバーに「開始」を記録）→ ②ストアで支払い（今は模擬ストア）→ ③ゲームがレシートをサーバーへ → ④サーバーが検証して GEMS を付与。付与はストアの取引IDの一意制約で1回だけ（同じレシートを何度送っても二重に付与しない）。検証と付与は1回のバッチ |
| 模擬ストア | 本番以外だけ。サーバーが署名したテスト用のレシートを発行し、検証でも署名を確かめる（ゲーム側でレシートを作れない）。画面に「テスト用・実際の請求なし」と表示 |
| Apple・Google | 検証の接続口（ストアごとの検証処理の差し替え口）だけ。実際の検証（App Store Server API・Google Play Developer API）はアプリと各ストアの設定ができてから。それまでは「未接続」として拒否 |
| 付与する通貨 | 価格分（例：¥1,200 なら 1,200）は有償GEMS（購入）、おまけ分（50）と初回ボーナスは有償GEMS（配布）として記録（Premium ガシャに使えるが、購入額には含めない）。会計・法務上の扱いは専門家の確認が前提 |
| 返金 | ストアからの返金通知（今は模擬）で、その購入で付与した GEMS を回収。残高が足りない分は「未回収」として記録（決定 57）。会員の返金は会員を即時終了 |
| 会員（定期購入） | 30日ごとの自動更新（決定 55）。ストアの「更新」「解約（期間終了まで有効）」「期限切れ」「返金」の通知で状態を変える。会員の特典（毎日 無償GEMS 20）はログインボーナスと一緒に1日1回 |
| Season Pass | 月単位・30段階・1段階 200 経験値。リーグ1回 100（1位 +50）、対戦報酬と同じく1日10リーグまで。プレミアム（800 GEMS・無償から先に、決定 56）は途中から買っても、それまでの段階の報酬を受け取れる。報酬は `reward_claims` で1回だけ |
| ガシャ管理 | 管理サイトで作成・編集・公開・終了。公開後の変更は新しい版として記録（決定 58）。版ごとに排出率・候補・価格・天井の写しを保存し、抽選履歴の版から当時の内容が分かる。排出率は合計100%でなければ保存できない |
| 売上分析 | 売上（総額・返金・純額）、日次・週次・月次、課金者数、課金率、ARPU、ARPPU、初回課金率、商品別の購入数、ガシャ別の有償GEMS消費、返金額、購入失敗率、未使用の有償GEMS。模擬ストアの購入は「模擬」と分けて表示 |
| 権限 | 商品の変更・ガシャの管理・返金の対応は owner・admin。購入の一覧（個人の情報）は users.read を持つ役割。売上の集計は viewer も見られる |
| 分析イベント | purchase_started・purchase_completed・purchase_failed・purchase_refunded・pass_purchased・membership_started 等を追加 |

## 4. 実装順序

1. shared：商品・会員・Season Pass の設定と報酬表（単体テスト）
2. api：マイグレーション 0007 → 商品・購入・模擬ストア・返金・会員 → Season Pass → ガシャ管理 → 売上分析（結合テスト）
3. web：ショップ（模擬ストア）、Season Pass、会員バッジ
4. admin：商品、購入・返金、売上、ガシャ管理
5. ブラウザでの確認、staging への公開と確認、ドキュメント、コミット
