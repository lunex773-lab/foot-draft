# オークション（仕様書「PLAYER AUCTION SYSTEM 開発引き継ぎ仕様 v1.0」）実装計画

置き場所：下のメニュー「ガシャ」の中のタブ（ガシャ／交換所／**オークション**）。
決定事項は `docs/02-decisions.md` の 97〜106。仕様書にない点の提案は「3. 仕様書にない点（提案）」。

## 1. 仕組み（ユーザー決定）

| 項目 | 内容 |
| --- | --- |
| 形 | 全ユーザー共通の1つの市場。最大8人の選手が同時に出品され、みんなで公開で競り上げる。落札した選手は自分のコレクションに入り、MATCH のチームで使える。DRAFT MATCH は今のまま（仕様書冒頭の「指名式ドラフトを変更」はしない） |
| 重複 | 持っている選手も落札でき、ガシャの重複と同じく +1 強化（最大 +5）。+5 の選手には入札できない |
| 資金 | オークション専用のコイン（COINS・GEMS とは別の財布と台帳）。最初に 100,000。足りない分は GEMS から交換（無償 → 有償（配布）→ 有償（購入）の順、1 GEMS = 10 コイン、一方通行）。お金で直接は買えない |
| 開始価格 | レアリティ別（暫定 COMMON 1,000・RARE 3,000・EPIC 8,000・LEGENDARY 20,000・ICON 40,000、管理画面で変更） |
| 入札者の表示 | 最高額の人の表示名と入札の回数を表示（自分は「あなた」） |

## 2. ルール（仕様書 2〜4、数値は管理画面で変更可）

| 項目 | 初期値 |
| --- | --- |
| 初期資金 | 100,000 |
| 同時出品 | 最大8人 |
| 入札時間 | 出品から30秒 |
| 延長 | 終了前10秒以内の入札で終了時刻を10秒延長 |
| 最低上乗せ | 今の最高額の5%か100コインの大きい方（最初の入札は開始価格以上） |
| GEMS 交換レート | 1 GEMS = 10 コイン |

- 入札すると、その額を仮押さえする（使える額 = 残高 − 仮押さえの合計）。仮押さえの合計が残高を超えないことはデータベースの制約でも保証する。
- 他の人に上回られたら、その人の仮押さえはすぐ解除。
- 終了時に最高額の人だけが支払い、同時に選手を付与（支払いと付与は1つのトランザクション。どちらかだけになることはない）。落札できなかった人は何も減らない。
- 自分が最高額の選手にはさらに入札できない。入札の取り消しはできない。
- 入札・延長・落札の判定はすべてサーバー（サーバーの時刻）。全部の入札を保存する。

## 3. 仕様書にない点（提案・変更できます）

| 項目 | 提案 |
| --- | --- |
| 出品の順番（偏りを抑えたランダム） | 「ランダム」の時：全300人をシャッフルして1人ずつ出品し、全員が1回ずつ出たら（＝市場の更新）またシャッフルする。落札された選手も、落札されなかった選手も次の更新で再出品される（同じ選手を何人でも持てるため）。同じ選手が同時に2枠に出ることはない |
| 誰も見ていない時 | 管理画面の設定（初期値：止める）。止める時は、誰も見ておらず入札もない間は新しい出品を止め、次に誰かが開いた時に再開（誰も見ていない間に ICON が流れてしまわないように）。入札がある出品は誰も見ていなくても時間どおりに終わって決済する |
| 落札の通知 | 画面を開いていれば上回られた時・落札した時にすぐ表示。閉じていた時は次に開いた時に「落札した選手」に表示 |
| 決済までに +5 になった時 | 入札後にガシャで +5 になった選手を落札したら、ガシャの重複と同じ Premium 交換ポイントを付与 |
| 交換のしかた | 入札で足りない時は、足りない分（GEMS 単位で切り上げ）を交換して入札するか確認する。オークション画面からいつでも交換もできる |
| 有償 GEMS の返金 | 交換済みのオークションコインは回収しない（返金時に回収できなかった GEMS は今までどおり「未回収」として記録） |
| 不正検知ログ | 拒否した操作（残高不足・最低額未満・終了後・自分の最高額への入札・連打・不正なメッセージ）と、怪しい動き（同じ通信元の複数アカウントが同じ出品に入札・短時間の大量入札）を記録。通信元はハッシュだけ保存 |
| テストデータのリセット | オークションの財布と仮押さえも初期化（次に開いた時に初期資金をもう一度受け取る） |

## 3-2. 管理画面からの運営（ユーザー決定 105）

| 操作 | 内容 |
| --- | --- |
| 開催・停止 | 市場を開く／止める。止めると新しい出品をしない（入札がある出品は時間どおりに決済） |
| 出品の方法 | 「ランダム」か「管理者が選ぶ」を切り替える。「管理者が選ぶ」の時は、管理者が選んだ選手の順番待ちの列から出品する（列が空なら新しい出品はなし。落札されなかった選手は列の最後に戻る）。列の追加・並べ替え・削除 |
| 出品の取り消し | 開催中の出品を取り消す（仮押さえはすべて解除、だれも支払わない。操作ログに記録） |
| 数値 | 初期資金・同時出品数・入札時間・延長・最低上乗せ・開始価格・交換レート・誰も見ていない時に止めるか |

変更・操作はすべて管理者の操作ログに記録。設定の変更は owner と admin だけ（viewer・support は見るだけ）。

## 4. 作り（既存の仕組みを再利用）

| 部分 | 内容 |
| --- | --- |
| 選手 | 既存の選手データベース（能力値・SIM の内部能力・レアリティ・カード画像）をそのまま使う |
| 付与 | ガシャと同じ強化の処理（user_collections、level +1、+5 の後は交換ポイント） |
| 市場の進行 | 新しい Durable Object（AuctionDO、市場に1つ）。入札を1つずつ順に処理し、終了時刻にアラームで決済。WebSocket（ハイバネーション）で全員に配信。切断しても状態はサーバーに残り、再接続で最新の状態を受け取る |
| データベース | マイグレーション 0012：オークションの財布（残高・仮押さえ、仮押さえ ≤ 残高の制約）と台帳、出品、入札（全履歴）、仮押さえ、落札結果、不正検知ログ、設定（app_settings） |
| 二重の防止 | 出品の状態は「開催中 → 落札／未落札」の一方通行（条件付き更新）、決済は出品ごとに1回（一意制約）、GEMS 交換はリクエスト ID で1回だけ、入札は DO で順番に処理し D1 のトランザクション（batch）で記録 |
| 認証 | 今のログインと WebSocket のチケット |

## 5. 画面

- ゲーム：ガシャのタブに「オークション」。上に自分の資金（使える額・仮押さえ中）と「GEMS から交換」。8枠のカード（カード画像・レアリティ・現在の最高額・最高額の人・残り時間のバー・次の最低額・「持っている → +1 強化」）。タップで入札画面（最低額・+5%・+10%・金額入力）。上回られた・落札したの表示。「入札中」「落札した選手」の一覧。ルールの説明
- 管理サイト「オークション」：総落札額・平均落札価格・レアリティ別の平均・選手別の落札価格・未落札の選手・プレイヤー別の残高と仮押さえ・入札履歴（ユーザー・選手で検索）・不正検知ログ・設定（初期資金・同時出品数・時間・延長・最低上乗せ・開始価格・交換レート。変更は操作ログに記録）

## 6. 進め方（各 Phase の終わりに型チェック・ビルド・テスト）

3. ゲーム画面
4. 管理サイト
5. 全体の回帰テスト、ブラウザ確認（iPhone の大きさ）、ドキュメント、staging に公開
